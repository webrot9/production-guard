# FPG001 — user-owned row looked up without its owner

**Invariant:** a row that belongs to a user is only ever read, changed or
deleted by a query that also names that user.

## The bug

```python
@router.get("/documents/{document_id}")
async def read_document(document_id: int, user: CurrentUser, db: DB):
    return await db.get(Document, document_id)
```

The route requires a signed-in user and never uses them. Any account can
read any document by counting upwards. This is IDOR (insecure direct object
reference), the most common access-control bug in APIs, and it survives code
review because nothing in the handler is wrong — something is missing.

## The fix

Put the owner in the query, so the database cannot return someone else's row:

```python
@router.get("/documents/{document_id}")
async def read_document(document_id: int, user: CurrentUser, db: DB):
    stmt = select(Document).where(Document.id == document_id, Document.owner_id == user.id)
    doc = (await db.execute(stmt)).scalar_one_or_none()
    if doc is None:
        raise HTTPException(status_code=404)
    return doc
```

- **404, not 403.** A 403 tells the caller the id exists. Treat "not yours"
  and "not there" the same.
- **One place for the filter.** When several routes read the same model,
  give its repository a `get_for_user(id, *, user_id)` and make it the only
  read the routers call. A router reaching for `session.get(Model, id)` or a
  bare `repo.get(id)` has then visibly bypassed it.
- **Updates and deletes too.** `update(Document).where(Document.id == id)`
  without the owner changes anyone's row; add the owner to the `WHERE`.
- **Tenant-scoped data** (rows that belong to an organisation): filter by
  the caller's organisation, and check membership in a dependency that
  takes the path's `{org_id}` — the rule recognises such a dependency.

## What the rule looks for

1. a route that identifies its caller — a dependency whose name says user,
   account, org, token, subject (`CurrentUser`, `Depends(get_current_user)`,
   `Security(...)`), including router-level dependencies;
2. a client-controlled id — a path parameter, or an `*_id` query parameter —
   reaching a lookup: `session.get(Model, id)`, a `select`/`update`/`delete`
   or `session.query(...)` chain that filters on it, a model classmethod
   (`Model.get(id)`), or a call into your own code that does one of those
   (followed up to three calls deep);
3. none of: the principal inside that lookup, a comparison between the id
   and the principal before it (`if user_id != user.id: raise`), a comparison
   between the row and the principal after it (`if doc.owner_id != user.id`),
   an authorisation helper given both (`ensure_owner(doc, user)`).

It does **not** report:

- routes with no identified caller (public by design, or a different bug);
- routes behind an admin dependency (`AdminDep`, `require_superuser`), or
  gated in the handler (`if not user.is_superuser: raise`);
- routes behind a permission dependency that reads the same path parameter
  (it is checking this row);
- models with no owner column — a public `Plan` read by id is fine;
- queries that filter on a publicity column (`Article.published.is_(True)`).

## Confidence

- **high** — the model was found and has an owner column (`user_id`,
  `owner_id`, `org_id`, … or a foreign key into a users-like table).
- **medium** — the model could not be resolved (reached through
  `self.model`, defined in a library), or it only records who created it
  (`author_id`, `creator_id`): whether that makes it private is a product
  decision. Confirm it before fixing or dismissing.

## Proving it

The `[[ownership]]` probe creates a row as one user and requests it as
another — read, change, delete — then checks, as the owner, that the row is
still there and unchanged. See [probes.md](probes.md).
